# Implementation Plan: Star Wars Explorer

**Branch**: `001-starwars-spa` | **Date**: 2026-05-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-starwars-spa/spec.md`

## Summary

Build a greenfield Angular 17 standalone SPA that lists Star Wars characters (paginated, 10/page) and films (all at once) from the public SWAPI REST API, presented with Angular Material v17 components, and optimised to meet Core Web Vitals thresholds (LCP ≤ 2.5 s, CLS ≤ 0.1, INP ≤ 200 ms). Two lazy-loaded routes (`/characters`, `/films`) served from a shared `AppComponent` shell. All data access through a single `SwapiService`. Unit tests with JEST at 100% coverage; E2E tests with MCP Playwright.

## Technical Context

**Language/Version**: TypeScript ~5.2 (Angular 17 bundled), Node.js ≥ 18.13

**Primary Dependencies**: Angular 17, Angular Material v17, Angular CDK v17, RxJS 7.x, `jest-preset-angular` (JEST adapter), `@playwright/test` (E2E via MCP Playwright)

**Storage**: No local persistence. In-memory `shareReplay(1)` cache for films observable; characters fetched per-page on demand.

**Testing**: JEST (unit, 100% coverage) + MCP Playwright (E2E, 3 user journeys)

**Target Platform**: Modern web browsers (Chrome 110+, Firefox 110+, Safari 16+, Edge 110+). SPA only — no SSR, no native mobile.

**Project Type**: Frontend web application (Single-Page Application)

**Performance Goals**: LCP ≤ 2.5 s | CLS ≤ 0.1 | INP ≤ 200 ms | Initial bundle ≤ 200 kB gzipped

**Constraints**: Standalone components only (no NgModule); OnPush change detection on all components; lazy-loaded routes via `loadComponent`; no NgRx or third-party state management; no UI libraries besides Angular Material

**Scale/Scope**: Greenfield, single developer, 2 screens, ~10 source files, ~82 SWAPI characters, ~6 SWAPI films
